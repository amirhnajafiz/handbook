## Quick Description (QD)

When you get a new VM, there are some settings you should apply before using it. In this page, I have listed the useful commands and setups I usually run the first time I use a VM.

## Installation

Install the SSH server (if not already installed):

```bash
sudo apt update && sudo apt install openssh-server
```

## Useful Tips/Commands (UToC)

### Check Network Configurations

```bash
ip addr show          # Show all network interfaces and IP addresses
ip route show         # Show current routing table (gateway, etc.)
cat /etc/resolv.conf  # Show current DNS settings
hostname -I           # Show assigned IP(s)
```

### SSH Settings

Check status:

```bash
sudo systemctl status ssh
```

Change the SSH config:

```bash
sudo nano /etc/ssh/sshd_config
```

Reload SSH after changes:

```bash
sudo systemctl restart ssh
```

#### Copy SSH Key

If you do not have a key pair yet, generate one on your local machine (see [SSH](05_ssh.md)):

```bash
ssh-keygen -t ed25519
```

Then copy your public key to the VM (use `-p` only if SSH listens on a non-default port):

```bash
ssh-copy-id -p <port> user@VM_IP
```

It will ask for your password one last time, then append the key to:

```text
~/.ssh/authorized_keys
```

Make sure the SSH server allows key authentication in `/etc/ssh/sshd_config` (these are the defaults on most distributions):

```text
PubkeyAuthentication yes
AuthorizedKeysFile .ssh/authorized_keys
```

Validate the config and restart SSH:

```bash
sudo sshd -t && sudo systemctl restart ssh
```

### Check Firewall

See status:

```bash
sudo ufw status verbose
```

Allow SSH first, so you do not lock yourself out when the firewall is enabled:

```bash
sudo ufw allow ssh
```

Enable the firewall:

```bash
sudo ufw enable
```

Allow a specific port (example: HTTP):

```bash
sudo ufw allow 80/tcp
```

Remove the rule:

```bash
sudo ufw delete allow 80/tcp
```

### Configure Gateway and DNS

Check the current gateway:

```bash
ip route | grep default
```

Set a new one:

```bash
sudo ip route replace default via 192.168.1.1
```

> A route set with `ip route` is lost on reboot. To make it permanent, use Netplan (Ubuntu) or `/etc/network/interfaces` (Debian and older systems).

Netplan example (`/etc/netplan/01-static.yaml`, then run `sudo netplan apply`):

```yaml
network:
  version: 2
  ethernets:
    eth0:
      addresses: [192.168.1.50/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 1.1.1.1]
```

`/etc/network/interfaces` example (then run `sudo systemctl restart networking`):

```text
iface eth0 inet static
    address 192.168.1.50
    netmask 255.255.255.0
    gateway 192.168.1.1
    dns-nameservers 8.8.8.8 1.1.1.1
```

> On systems that use `systemd-resolved`, `/etc/resolv.conf` is managed automatically. Use `resolvectl status` to see the effective DNS servers.

### Disk Info

Show disk usage:

```bash
df -h
```

Show detailed disk and partition info:

```bash
lsblk
```

### RAM Info

Show total and used memory:

```bash
free -h
```

Detailed memory info:

```bash
cat /proc/meminfo
```

### CPU Info

Summary:

```bash
lscpu
```

Detailed CPU info:

```bash
cat /proc/cpuinfo
```

### System Info

Show system info:

```bash
hostnamectl
```

Show overall hardware info:

```bash
sudo lshw -short
```

Show kernel version:

```bash
uname -r
```

Show OS version:

```bash
cat /etc/os-release
```
