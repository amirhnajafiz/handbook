# Ext4

## Quick Description (QD)

**Ext4** stands for Fourth Extended Filesystem, the fourth major iteration of the ext family used in Linux. On a normal Linux system, Ext4 support is already installed by default.

```sh
mkfs.ext4 -V
grep ext4 /proc/filesystems
```

### Key Features of Ext4

- Journaling: Keeps a log (journal) of changes before applying them, which helps avoid corruption after power loss.
- Large file and volume support: Files up to 16 TiB, volumes up to 1 EiB (with 4 KiB blocks).
- Extents: Stores large contiguous blocks more efficiently than older systems.
- Backward compatibility: Can mount Ext3 and Ext2 filesystems.
- Delayed allocation: Groups small writes into bigger chunks to improve performance.
- Checksums: Used for the journal (and, optionally, metadata) to detect corruption.

Ext4 is the default on most Linux distributions because it is reliable, well supported, and balanced between speed and safety.

## Useful Tips/Commands (UToC)

### Formatting a Disk or Partition with Ext4

If you have a raw disk, list the disks and (optionally) create a partition first:

```sh
lsblk
sudo fdisk /dev/sdb
```

Then format the partition:

```sh
sudo mkfs.ext4 /dev/sdb1
```

> Warning: This erases any existing data on `/dev/sdb1`.

### Mounting It

Once it is formatted, you mount it to a directory so you can use it:

```sh
sudo mkdir /mnt/mydisk
sudo mount /dev/sdb1 /mnt/mydisk
```

Now `/mnt/mydisk` acts like a normal folder, but its contents are stored on that Ext4 filesystem. To mount it at boot, add it to `/etc/fstab` (preferably by UUID, which you can get from `blkid`).

### Inspecting a Filesystem

Show the superblock information (block size, inode size, features):

```sh
sudo tune2fs -l /dev/sdb1
```

Check the filesystem (unmount it first):

```sh
sudo e2fsck -f /dev/sdb1
```

## Examples (e.g.,)

### Virtual Disk

We will make a virtual disk image, format it as Ext4, and mount it.

```bash
# make a 2GB sparse image file
truncate -s 2G ext4_test.img

# format it as Ext4 (-F: do not ask for confirmation, since it is a regular file)
mkfs.ext4 -F ext4_test.img

# make a mount point
sudo mkdir /mnt/ext4test

# mount it using a loop device
sudo mount -o loop ext4_test.img /mnt/ext4test
```

> Now `/mnt/ext4test` is your sandbox Ext4 filesystem.

Find the loop device that was assigned to it:

```bash
losetup -j ext4_test.img
```

You can then inspect the filesystem (replace `/dev/loop0` with the device printed above):

- **Space and inode usage:**

  ```bash
  df -h /mnt/ext4test
  df -i /mnt/ext4test
  ```

- **Block size, inode size and features:**

  ```bash
  sudo tune2fs -l /dev/loop0 | grep -E "Block size|Inode size|Filesystem features"
  ```

- **Journal statistics (jbd2):**

  ```bash
  cat /proc/fs/jbd2/loop0-8/info
  ```

  The directory name is `<device>-<journal inode>` and may differ on your system; list `/proc/fs/jbd2/` to see it.

- **Metadata of a file:**

  ```bash
  sudo touch /mnt/ext4test/test_file
  sudo debugfs -R "stat /test_file" /dev/loop0
  ```

When you are done:

```bash
cd ~
sudo umount /mnt/ext4test
sudo rmdir /mnt/ext4test
```

Your `ext4_test.img` still holds the data if you want to inspect it later. To remove it:

```sh
rm ext4_test.img
```
